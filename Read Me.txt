DVSA Appointment Setter - Operating Notes
========================================

This software is a headful browser assistant for the DVSA practical driving test service. It opens the official GOV.UK/DVSA flow, lets the learner complete any security steps, watches the appointment/results page for preferred text, and alerts when it sees a possible match.

Important use notes
-------------------
Use this only for your own driving test booking. GOV.UK says the learner must make appointment changes themselves and must not book, change, swap, or cancel a car driving test for someone else.

The program does not bypass payment screens, or final confirmation pages. Review the browser yourself before you change, book, pay for, or confirm anything.

Setup
-----
1. Install Python 3.11 or newer.
2. Open PowerShell.
3. Go to the engine folder:

   cd "D:\work\Projects\DSVA Bot\Software\Core Engine"

4. Install the Python dependency:

   python -m pip install -r requirements.txt

5. Install the Playwright browser:

   python -m playwright install chromium

Configuration
-------------
The starter config is:

   Core Engine\config.example.json

For normal use, make your own local copy:

   copy "config.example.json" "config.local.json"

Then edit config.local.json.

Useful settings:

- search.start_url
  Default is https://www.gov.uk/change-driving-test
  For a new practical test booking, use https://www.gov.uk/book-driving-test

- search.preferred_test_centres
  Add the test centre names you care about, for example:
  "Birmingham Kings Heath" or "London Mill Hill"

- search.preferred_keywords
  Add words that should appear on a useful result page, for example:
  "available", "change to this test", or "book this test"

- search.preferred_date_from and search.preferred_date_to
  Optional date range in YYYY-MM-DD format.

- search.poll_seconds
  How long to wait between checks. Keep this respectful. The app will not accept less than 60 seconds.

- search.rate_limit_jitter_seconds
  Adds a small random delay after each check so monitoring does not hit the service on an exact fixed beat.

- search.error_backoff_seconds
  Extra wait used after a page reload or page text read fails. This must be at least the poll_seconds value.

- search.rate_limit_cooldown_seconds
  Longer pause used when the visible page says things like search limit reached, too many requests, or try again later.

- proxy.enabled
  Set to true only if you have a proxy you are allowed to use.

- proxy.mode
  Use "off", "local", "single", "provider_rotating", or "rotating_list".

- proxy.local_server
  Local proxy address for tools like a local VPN/proxy client, for example:
  http://127.0.0.1:8080

- proxy.server
  Put the single proxy or provider-managed rotating endpoint here, for example:
  http://host:port
  socks5://host:port

- proxy.servers
  Auto rotator list. Add one proxy per line in the UI, or one string per item in JSON.
  The app selects a proxy from this list each time the assistant launches.
  For two paid proxies, set proxy.mode to "rotating_list" and add both proxy endpoints.

- proxy.username and proxy.password
  Fill these if your proxy provider needs authentication.

- proxy.provider_managed_rotating_endpoint
  Leave this true when your proxy company gives you one endpoint that rotates automatically on their side.

- proxy.rotation_strategy
  Use "round_robin" to step through the auto rotator list, or "random" to pick randomly.

- browser.channel
  Recommended: "chrome" for Chrome Web Store extensions and manual browsing. You can also use "chromium" or "msedge". Chrome or Edge must already be installed locally when selected.

- browser.startup_mode
  Recommended: "manual". It opens a search/start page first, then waits while you browse to DVSA yourself. Use "service_url" only when you want the older automatic GOV.UK start.

- browser.manual_start_url
  The page opened in manual mode. The default is a Google search for DVSA change driving test. You can replace it with another HTTPS search page or a direct official URL.

- browser.extension_store_url
  Chrome Web Store page to open when preparing extensions. Use the main store page or a specific extension page, for example:
  https://chromewebstore.google.com/

- browser.open_extension_store_on_launch
  Set this to true if you want the assistant browser to open the Chrome Web Store first. Install or check the extension manually, then press Enter in the assistant console and browsing will continue.

- browser.enable_installed_extensions
  Recommended: true. This allows extensions already installed in the assistant browser profile to run. This is the closest mode to a normal Chrome browser session. Extension behavior still depends on the extension, browser channel, and Chrome Web Store support.

- browser.load_unpacked_extensions
  Set this to true to load unpacked extension folders at browser startup. This uses Playwright Chromium and expects each folder to contain a manifest.json file.

- browser.extension_paths
  Add one unpacked extension folder path per item in JSON, or one per line in the UI. When this is enabled, use the Chromium browser option. Do not use extensions to bypass DVSA security checks or human verification.

- browser.manual_verification_pause
  Leave this true so the assistant pauses when the page asks for CAPTCHA/security/human verification. Complete the check yourself in the visible browser, then press Enter in the assistant console.

Run
---
Main launcher:

   Launcher.bat

This is kept in the Software root folder as the designated launcher.
It also checks that the instruction file exists before starting the UI.

Pleasant UI:

   Core Engine\start_ui.bat

Or from the Core Engine folder:

   python -m dvsa_appointment_setter.ui_server

The UI opens at:

   http://127.0.0.1:8765

Use the Day/Night switch in the top right to change the theme.

Command line:

From the Core Engine folder:

   python -m dvsa_appointment_setter.cli --config config.local.json

Or double-click:

   Core Engine\run.bat

Basic workflow
--------------
1. Start the program.
2. A Chrome browser opens to the manual start/search page.
3. Search for DVSA or open the official GOV.UK/DVSA service yourself.
4. Install, open, or use Chrome extensions manually if needed.
5. Complete any DVSA security or login steps yourself.
6. Navigate to the page where appointment slots or result text is visible.
7. Return to PowerShell and press Enter.
8. The program checks the visible page text against your centre, keyword, and date settings.
9. If it finds a possible match, it beeps and prints the matched text.
10. Review and confirm any appointment action yourself in the browser.
11. After you personally book or change an appointment, record it in the Appointment Dashboard.

Manual browser workflow
-----------------------
Use this when you want to search for DVSA manually or prepare browser extensions before monitoring.

1. In the UI, set Browser to Google Chrome and Browser start to Manual search/navigation.
2. Keep Allow installed extensions ticked.
3. Optional: tick Open Chrome Web Store before DVSA if you want to install or check extensions first.
4. Launch the assistant.
5. Use the browser normally: search the web, open the official GOV.UK/DVSA service, sign in, and complete any security checks yourself.
6. Go to the appointment/results page where slots are visible.
7. Return to the assistant console and press Enter. The app starts monitoring from the page currently open in the browser.

Appointment dashboard
---------------------
The dashboard stores manually recorded completed appointment work in:

   Storage\Appointment_YYYY-MM-DD.csv

The dashboard shows today's count, a remaining count toward 10 records, and the proxy note for the next browser session.

The app cannot change a browser proxy mid-session. With Auto rotator list mode, each new assistant launch selects the next proxy, so close and relaunch the assistant between completed appointment sessions if you need the next proxy to be used.

One-check test run
------------------
Use this to make sure the setup works without leaving the monitor running:

   python -m dvsa_appointment_setter.cli --config config.local.json --once

Logs
----
Runtime activity is written to:

   Logs\process Log.md

Development notes are kept in:

   Logs\development log.md

These logs are file-only and are not displayed on the local UI screen.

Development routine
-------------------
Before development work starts, check:

   ..\Instructions\instructions.md

After finishing a change, run three review passes: test, look for one practical improvement, apply it if useful, and record the pass in the log files.

To run the repeatable three-pass review:

   Core Engine\review_3x.bat

Or from the Core Engine folder:

   python -m dvsa_appointment_setter.self_check --stamp

Troubleshooting
---------------
If Playwright is missing:

   python -m pip install -r requirements.txt
   python -m playwright install chromium

If the bot says the config URL is not allowed, use an official GOV.UK or DVSA service URL.

If no matches are found, adjust the preferred test centre names, keywords, or date range in the config.
